# Grassroots

Political campaign software for voter outreach and volunteer management. A pnpm + Turborepo monorepo: NestJS backend, React (Vite + TanStack Router) frontend, and shared packages, glued together by generated OpenAPI types.

## Repo map

```
grassroots-backend/           NestJS API (Postgres via TypeORM, Google OAuth)
grassroots-backend-e2etests/  Backend e2e tests (vitest, needs a running backend + DB)
grassroots-frontend/          React SPA (Vite, TanStack Router)
grassroots-shared/            Code shared between backend and frontend (built with swc)
grassroots-shared-net/        Shared network/API types (built with swc)
openapi-paths/                Generated OpenAPI path types (OpenAPI.gen.ts)
eslint_rules/                 Custom ESLint rules (built with swc, has its own vitest tests)
docker/                       Dev/CI compose files (caddy, ngrok, app container)
doc/                          Dependency graph and build notes
```

## Commands (run from repo root)

| What | Command |
|---|---|
| Install | `pnpm install` (runs backend `postinstall`, which bootstraps generated files) |
| Build everything | `pnpm exec turbo build` |
| Type-check + lint | `pnpm run check` (`turbo tsc && turbo lint`) |
| Lint (fix) | `pnpm run lint` (root eslint; depends on `eslint_rules` being built) |
| Format | `pnpm run format` (prettier) |
| Tests | `MODE=test pnpm exec turbo test --env-mode=loose` (depends on `grassroots-backend#gen-files-only`) |
| One package's tests | `pnpm --filter eslint_rules test` etc. |

In sandbox/cloud sessions, always pass `MODE=test` and `--env-mode=loose` to turbo commands: `gen-files-only` boots the backend against the local Postgres using `.env.test` + `.env.test.local`, and turbo's strict env mode would strip `MODE`.

## Generated files — read before debugging type errors

- `grassroots-backend/src/FormattedMetadata.gen.ts` and `src/util/LastDependencyUpdateTime.ts` are bootstrapped as stubs by `postinstall` and regenerated by `gen-metadata` / `gen-files-only`.
- `openapi-paths/src/OpenAPI.gen.ts` is generated from the backend's OpenAPI output.
- Never hand-edit `*.gen.ts` files; regenerate them. If types look impossibly wrong, the generated files are probably stale stubs.

## What runs where

- **Works in a sandbox/cloud session:** `pnpm install`, builds, type-check, lint, prettier, and unit tests (including backend tests — the session-start hook runs a local Postgres on `localhost:5432` with the `.env.test` credentials and applies migrations).
- **Needs Docker (local only):** the full dev stack (`docker/compose.dev.yaml`: caddy, app container, optional ngrok), backend e2e tests against a running backend, and Google OAuth callback flows.
- Local dev flow: fill `.env.development.local` from the sample, then use the docker compose setup (see README.md).

## Conventions

- Custom lint rules live in `eslint_rules/` and are part of `//#lint`'s dependency chain; build them before running eslint directly.
- Dependency versions are kept in sync across packages with syncpack (`.syncpackrc.js`).
- Husky + lint-staged run prettier/eslint on commit; CI (`.github/workflows/ci.yml`) must pass the same checks.
